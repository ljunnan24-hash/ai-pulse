# RawItem 与抓取去重说明

## 分层关系

1. **源级（feed URL）**  
   当前仍对每个配置的 feed **全量 HTTP 请求**（未启用 `feed_state` / ETag / `Last-Modified`）。同一配置里若出现重复 feed URL，仅在**单次 run 内**第二次起会跳过请求，并记 `feed_crawl_runs.health_status=skipped_duplicate_feed`。

2. **条目级（collect 合并列表）**  
   单次 run 内对合并后的 item 用稳定键去重：优先 **规范化 URL 的 SHA256**（`item_stable_dedupe_key`），无 `link` 时用 **规范化标题哈希**。同一篇文章不同 `utm_*`、fragment 等会合并为同一键。

3. **RawItem 入库前**  
   `daily_rankings` 在 `bulk_insert_mappings` 前调用 `filter_new_items_for_daily_rankings`：对照 `raw_items` 中 `issue_id IS NULL` 的已有行，若 **`normalized_link_hash`**、**`link` 原文** 或 **`normalized_link`**（回填后可命中）任一匹配则跳过插入。仅对**真正新增**的条目打分、组 `mappings` 并插入。

4. **GlobalEvent**  
   `find_or_create_global_for_raw` / `upsert_global_events_from_raw_items` 做的是**事件维度合并**，与 RawItem 是否重复入库是不同层；本仓库本轮改动**不**改变 GlobalEvent 逻辑。

## 数据库

- 迁移：`sql/migrations/2026-05-15_raw_items_dedupe_columns.sql` 为 `raw_items` 增加可空列 `normalized_link`、`normalized_link_hash` 及普通索引（**无 UNIQUE**，避免历史脏数据导致迁移失败）。
- 新插入行会写入上述两列；旧行为空时，查重仍可通过 **`link` 原文** 命中一部分重复。

## 后续可做（未实现）

- 按 feed 维度的条件请求：`feed_state`、`ETag`、`Last-Modified` 等，以减少带宽与源站压力。

## 运维

上线前请在目标库执行上述迁移；ORM 已包含对应字段，未迁移时 job 会按表结构探测列，缺失时退化为仅 `link` + 批次内键查重。
